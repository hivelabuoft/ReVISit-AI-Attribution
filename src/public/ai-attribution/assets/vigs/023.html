🔒 Scenario Slide Deck — Thread Safety Mechanism

📝 The Assignment

  • Fourth-year operating systems course
  • Students learn to prevent race conditions in multi-threaded programs
  • Task: implement a thread-safe counter

🧠 The Starting Point

  • Student understands the concepts already
  • Wants a solution that optimizes for high-speed reading
  • Asks the AI for a locking strategy

🤖 First AI Interaction

  • AI proposes a standard locking approach
  • Student rejects it — too slow for the system's needs
  • Student prompts for a "lightweight" alternative

🔄 Iterating with the AI

  • Second suggestion also rejected — ignores memory constraints
  • Multiple rounds evaluating trade-offs between speed and safety
  • AI finally outlines a "reader-writer" logic fitting all criteria

💻 Writing & Submission

  • Student writes the code themselves
  • Strictly translates the steps from the AI's final explanation into C syntax
  • No modifications added to the logic beyond the AI's outline

📖 Original Vignette Text

In a fourth-year operating systems course, students learn to prevent race conditions in multi-threaded programs. The task is to implement a thread-safe counter. The student understands the concepts, but wants a solution that optimizes for high-speed reading. They ask the AI for a locking strategy, but reject the first standard proposal as being too slow for the system's needs. The student prompts for a 'lightweight' alternative, then rejects the suggestion again when the second suggestion ignores memory constraints. After multiple rounds of evaluating the trade-offs between speed and safety, the AI outlines a specific 'reader-writer' logic that fits all criteria. The student then writes the code themselves, strictly translating the steps from the AI's final explanation into C syntax without adding their own modifications to the logic.
