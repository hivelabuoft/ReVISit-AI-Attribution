📋 The Assignment

  • Includes users who rely on screen readers
  • Task: check an existing webpage and fix accessibility issues
  • Issues include missing descriptive labels for buttons and incorrect heading order

🤔 The Starting Point

  • Student is new to accessibility guidelines
  • Doesn't understand why simple HTML tags might not be enough
  • Consults an AI to explain the error

  • Student rejects this — it conflicts with the site's minimalist design

🔄 Iterating with the AI

  • Student iterates with the AI a couple more times
  • Prompts the AI for a solution that works for screen readers
  • Solution must remain invisible to sighted users

📖 Original Vignette Text

In a third-year web design course, students learn to make websites usable for everyone, including people who use screen readers. The instructor assigns a task to check an existing webpage and fix issues like missing descriptive labels for buttons and incorrect heading order. The student is new to these accessibility guidelines and doesn't understand why simple HTML tags might not be enough. They consult an AI to explain the error, but reject the tool's initial suggestion to add standard text labels, stating that this conflicts with the site's minimalist design. The student iterates with the AI a couple more times, prompting it to propose a solution that works for screen readers but remains invisible to sighted users. The student strictly follows the logic of this negotiated solution to manually update the code.
